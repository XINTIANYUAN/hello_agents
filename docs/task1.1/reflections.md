## 用三个问题理解智能体分类

| 分类维度 | 用来回答的问题 | 我的理解 |
| --- | --- | --- |
| 内部决策架构 | 行动依据是什么？ | 简单反射智能体根据当前输入匹配规则。基于模型的反射智能体维护内部状态。基于目标的智能体寻找能达成目标的行动。基于效用的智能体还能给结果评分，权衡多项要求。学习能力可以与这些架构结合。 |
| 时间与反应性 | 需要立刻响应，还是需要先规划？ | 反应式设计适合对当前事件作出快速响应。规划式设计会考虑后续步骤。混合式设计可以分别处理高层规划和即时反馈。 |
| 知识表示 | 决策所用的知识如何表示？ | 神经网络参数隐含统计模式，符号表示可以明确表达规则和约束。旅行助手里，模型生成文本，程序按显式格式解析动作。这提供了观察两类机制如何配合的入口。 |

这三个维度可以用来同时描述一个系统。比如在灵巧手仿真里，轨迹规划模块可以先寻找满足目标的候选动作，仿真环境在发生碰撞时即时反馈。上层智能体读取反馈并决定是否请求新的候选轨迹，规划、反馈速度和约束表达分别有了可讨论的对象。 [第一章 1.1.3 智能体的类型](https://github.com/datawhalechina/hello-agents/blob/2eb1c7547018b519b85cb57acf5533f12d65bf8e/docs/chapter1/%E7%AC%AC%E4%B8%80%E7%AB%A0%20%E5%88%9D%E8%AF%86%E6%99%BA%E8%83%BD%E4%BD%93.md#113-智能体的类型)

## 用 PEAS 检查旅行助手的循环

把旅行助手放进 PEAS 里，性能度量是查到北京的当前天气，并依据它给出合适的景点。环境包括会随时间变化的天气和网络搜索内容。执行器是发出查询的 Python 工具，传感器是用户输入和 API 返回数据进入程序的接口。天气工具的返回值同时也是第二次调用的输入依据。 [第一章 1.2.1 任务环境定义](https://github.com/datawhalechina/hello-agents/blob/2eb1c7547018b519b85cb57acf5533f12d65bf8e/docs/chapter1/%E7%AC%AC%E4%B8%80%E7%AB%A0%20%E5%88%9D%E8%AF%86%E6%99%BA%E8%83%BD%E4%BD%93.md#121-任务环境定义)

我会用一条证据链来读终端记录。先找 `get_weather` 的执行结果，再检查下一轮 `get_attraction` 的天气参数是否来自这条结果，最后检查 `Finish` 的天气和推荐分别有没有对应的依据。`Thought` 里可读到模型给出的行动说明，`Action` 和 `Observation` 则能用来核对程序执行了什么、实际得到了什么。实时数据与课程截图有差异时，这套检查依然成立。 [第一章 1.2 智能体的构成与运行原理](https://github.com/datawhalechina/hello-agents/blob/2eb1c7547018b519b85cb57acf5533f12d65bf8e/docs/chapter1/%E7%AC%AC%E4%B8%80%E7%AB%A0%20%E5%88%9D%E8%AF%86%E6%99%BA%E8%83%BD%E4%BD%93.md#12-智能体的构成与运行原理) · [第一章 1.3.4 运行案例分析](https://github.com/datawhalechina/hello-agents/blob/2eb1c7547018b519b85cb57acf5533f12d65bf8e/docs/chapter1/%E7%AC%AC%E4%B8%80%E7%AB%A0%20%E5%88%9D%E8%AF%86%E6%99%BA%E8%83%BD%E4%BD%93.md#134-运行案例分析)
