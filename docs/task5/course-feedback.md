# Task5 课程内容反馈

第五章用不同任务展示了平台编排的用途。Coze 简报能观察多源数据汇总，Dify 个人助手能观察分类路由，FastGPT 能观察检索片段，n8n 邮件助手能观察触发、状态和执行。建议在这些案例中补充统一的输入输出样例和验收条件，让读者能同时核对画布配置与实际结果。 [第五章 基于低代码平台的智能体搭建](https://github.com/datawhalechina/hello-agents/blob/2eb1c7547018b519b85cb57acf5533f12d65bf8e/docs/chapter5/%E7%AC%AC%E4%BA%94%E7%AB%A0%20%E5%9F%BA%E4%BA%8E%E4%BD%8E%E4%BB%A3%E7%A0%81%E5%B9%B3%E5%8F%B0%E7%9A%84%E6%99%BA%E8%83%BD%E4%BD%93%E6%90%AD%E5%BB%BA.md)

- **为简报补充日期过滤和材料不足的路径。** Coze 示例要求固定数量的新闻、论文和项目，也用具体日期演示输出。建议显式传入运行日期与时区，保留条目的发布时间和原始链接，再规定去重方式。测试样例可以包含过期条目、重复链接和空结果，数量不足时列出实际找到的内容及缺项原因。这样能检查「今日」和「最新」是否有来源支持。 [第五章 5.2.2 每日 AI 简报案例](https://github.com/datawhalechina/hello-agents/blob/2eb1c7547018b519b85cb57acf5533f12d65bf8e/docs/chapter5/%E7%AC%AC%E4%BA%94%E7%AB%A0%20%E5%9F%BA%E4%BA%8E%E4%BD%8E%E4%BB%A3%E7%A0%81%E5%B9%B3%E5%8F%B0%E7%9A%84%E6%99%BA%E8%83%BD%E4%BD%93%E6%90%AD%E5%BB%BA.md#522-构建每日ai简报助手)
- **为 Dify 的路由和变量映射提供一组对照输入。** 可以给每个模块列出字段名称、类型和来源，配上正常请求、缺少参数的请求，以及同时包含两个任务的请求。分类结果应能对照预期路径，下游使用的变量也应在节点运行记录中看到。文案模块的长度要求可以随用途配置，例如短通知与长介绍各给一个样例，并核对原始事实是否完整保留。 [第五章 5.3.2 Dify 个人助手案例](https://github.com/datawhalechina/hello-agents/blob/2eb1c7547018b519b85cb57acf5533f12d65bf8e/docs/chapter5/%E7%AC%AC%E4%BA%94%E7%AB%A0%20%E5%9F%BA%E4%BA%8E%E4%BD%8E%E4%BB%A3%E7%A0%81%E5%B9%B3%E5%8F%B0%E7%9A%84%E6%99%BA%E8%83%BD%E4%BD%93%E6%90%AD%E5%BB%BA.md#532-构建一个超级智能体个人助手) · [Dify 问题分类器文档](https://docs.dify.ai/en/cloud/use-dify/nodes/question-classifier)
- **修正 n8n 的触发节点数量说明。** 5.5.1 写到一个工作流必须且只能有一个触发节点。n8n 官方文档说明，一个工作流可以包含多个触发节点，每次执行由相应事件触发其中一个。建议补一个手动入口与事件入口共用处理链的示意，说明不同入口怎样提供一致的后续字段。 [第五章 5.5.1 n8n 的节点与工作流](https://github.com/datawhalechina/hello-agents/blob/2eb1c7547018b519b85cb57acf5533f12d65bf8e/docs/chapter5/%E7%AC%AC%E4%BA%94%E7%AB%A0%20%E5%9F%BA%E4%BA%8E%E4%BD%8E%E4%BB%A3%E7%A0%81%E5%B9%B3%E5%8F%B0%E7%9A%84%E6%99%BA%E8%83%BD%E4%BD%93%E6%90%AD%E5%BB%BA.md#551-n8n-的节点与工作流) · [n8n 官方节点类型说明](https://github.com/n8n-io/n8n-docs/blob/main/docs/connect/create-nodes/plan-your-node/choose-a-node-type.md)
- **把知识、会话和执行状态画成三个可检查的对象。** 邮件案例已经分别配置向量库与线程记忆，可以进一步标出它们保存什么、键的范围、何时写入，以及重启后会怎样。执行状态还可记录邮件标识和处理结果，用重复输入与中途失败的测试检查是否会重复回复。官方文档明确说明 Simple Vector Store 的数据不持久化、存储键属于实例范围，这些条件适合与后面的持久化习题连在一起。 [第五章 5.5 n8n 邮件助手案例](https://github.com/datawhalechina/hello-agents/blob/2eb1c7547018b519b85cb57acf5533f12d65bf8e/docs/chapter5/%E7%AC%AC%E4%BA%94%E7%AB%A0%20%E5%9F%BA%E4%BA%8E%E4%BD%8E%E4%BB%A3%E7%A0%81%E5%B9%B3%E5%8F%B0%E7%9A%84%E6%99%BA%E8%83%BD%E4%BD%93%E6%90%AD%E5%BB%BA.md) · [n8n Simple Vector Store 文档](https://docs.n8n.io/integrations/builtin/cluster-nodes/root-nodes/n8n-nodes-langchain.vectorstoreinmemory)
- **为配套文件和界面操作补充复现信息。** 建议在案例旁写明平台版本或使用日期、插件名称、导入文件入口和需要重新绑定的配置。Coze 图 5.12 的图片地址以 `ttps://` 开头，Dify 的工作流链接使用了相对路径 `code/chapter5/HelloAgent_difyCase.yml`，可以修正为仓库中的对应文件地址。这样在界面调整后，读者仍能从配套文件核对节点和字段。 [第五章配套文件目录](https://github.com/datawhalechina/hello-agents/tree/2eb1c7547018b519b85cb57acf5533f12d65bf8e/code/chapter5) · [Dify 配套工作流](https://github.com/datawhalechina/hello-agents/blob/2eb1c7547018b519b85cb57acf5533f12d65bf8e/code/chapter5/HelloAgent_difyCase.yml)
