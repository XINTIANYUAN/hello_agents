# Task1 学习心得

## 从模型回答到智能体循环

前言把课程的出发点放在构建能规划和调用工具的应用上。第一章的旅行助手用一个具体任务演示了这个目标。程序先查北京天气，再根据查到的天气推荐景点。这个例子让我对「智能体」有了更具体的理解。模型提出下一步行动，Python 程序解析行动并调用工具，再把工具返回值放回上下文。下一轮如何行动，取决于程序刚刚得到的信息。 [课程前言](https://github.com/datawhalechina/hello-agents/blob/main/docs/%E5%89%8D%E8%A8%80.md) · [第一章 初识智能体](https://github.com/datawhalechina/hello-agents/blob/main/docs/chapter1/%E7%AC%AC%E4%B8%80%E7%AB%A0%20%E5%88%9D%E8%AF%86%E6%99%BA%E8%83%BD%E4%BD%93.md)

顺着 `Thought → Action → Observation → Finish` 看，`Thought` 提示模型打算做什么，`Action` 表达程序可以执行的请求，`Observation` 记录实际执行结果。最值得细读的是两个工具之间的数据流。天气工具给出的天气状态进入下一轮上下文，景点工具再用这个状态缩小查询范围。有了这样的执行轨迹，读到最终推荐时，可以回头检查天气是否真的查到、推荐依据从哪里来。 [第一章示例代码](https://github.com/datawhalechina/hello-agents/blob/main/code/chapter1/FirstAgentTest.py)

## 环境配置也是系统的一部分

这个示例短，却已经连接了 Python 环境、模型接口、天气接口和搜索服务。排查时，我会按依赖导入、模型响应、工具返回、循环结束的顺序检查。比如模型已经返回 `Action`，下一步就该查看工具收到的参数和返回值。这样也更容易理解为什么要把凭证放进环境变量，把默认配置和启动步骤写进仓库。准备好对应的服务配置后，读者就能在自己的电脑上沿着同样的步骤复现。 [Extra07 环境配置](https://github.com/datawhalechina/hello-agents/blob/main/Extra-Chapter/Extra07-%E7%8E%AF%E5%A2%83%E9%85%8D%E7%BD%AE.md)

## 从数字孪生和轨迹任务出发

一个适合后续练习的场景是灵巧手抓取仿真。智能体先读取目标物体与场景状态，再请求轨迹模块给出候选轨迹。数字孪生环境返回碰撞、关节限位和抓取稳定性等结果，智能体据此请求调整或提交本轮报告。这样可以复用旅行助手里的循环结构，并给每次行动留下可检查的观察值。轨迹计算、碰撞检测和控制仍由各自的模块承担，智能体负责选择操作及汇总结果。首个可评估的目标可以定得很小，比如固定同一场景，检查每项推荐是否都引用了仿真返回的验证结果。
