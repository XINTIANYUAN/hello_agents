# Task4 课程内容反馈

第四章复用一个模型客户端，分别展示工具驱动、先规划后执行、评审后修订的控制流程。搜索、算术和素数代码三个例子都有清楚的输入与目标，适合让学员逐步观察状态怎样进入下一次提示。课程已经讨论格式解析、执行成本和迭代上限，下面几项补充可以把这些讨论落到更具体的检查上。 [第四章 智能体经典范式构建](https://github.com/datawhalechina/hello-agents/blob/2eb1c7547018b519b85cb57acf5533f12d65bf8e/docs/chapter4/%E7%AC%AC%E5%9B%9B%E7%AB%A0%20%E6%99%BA%E8%83%BD%E4%BD%93%E7%BB%8F%E5%85%B8%E8%8C%83%E5%BC%8F%E6%9E%84%E5%BB%BA.md)

- **给 ReAct 补充一组格式失败示例。** 配套代码用 `startswith("Finish")` 判断结束，再用正则提取括号内容。可以提供 `Finish`、`Search[]`、一轮包含多个 `Action` 等输入，要求解析器报告具体原因，并只执行一条有效行动。这样能把提示词里的协议和程序实际接受的格式对应起来。 [第四章 ReAct.py 上游代码](https://github.com/datawhalechina/hello-agents/blob/2eb1c7547018b519b85cb57acf5533f12d65bf8e/code/chapter4/ReAct.py)
- **让计划与执行结果都通过明确检查。** `Planner` 当前只检查解析结果是否为列表，`[1]` 这样的结果也会通过。建议检查每项为非空字符串。`Executor` 会把模型调用失败后的空字符串记入历史并显示步骤完成，可以补一条中途失败的示例，说明停止、重试或重规划由哪一段代码负责。 [第四章 Plan_and_solve.py 上游代码](https://github.com/datawhalechina/hello-agents/blob/2eb1c7547018b519b85cb57acf5533f12d65bf8e/code/chapter4/Plan_and_solve.py)
- **把反思结论和验收结果一起用于停止。** 当前的子串判断会让「并非无需改进，还需处理边界输入」触发结束。可以把评审结果分成是否通过、问题列表和修改建议，再明确解析是否通过。素数示例还可以补充固定输入与预期输出，并比较初稿和修订稿的结果。算法效率的改进也应附上输入规模和测量方法。 [第四章 Reflection.py 上游代码](https://github.com/datawhalechina/hello-agents/blob/2eb1c7547018b519b85cb57acf5533f12d65bf8e/code/chapter4/Reflection.py)
- **说明示例中的记忆怎样影响后续调用。** `Memory` 保存了执行和评审记录，也定义了 `get_trajectory`，修订提示实际使用的是最近一版代码和本轮反馈。建议在图中标出保存的记录、实际传入模型的字段，以及下一项任务开始时怎样初始化。还可以用一轮实验展示加入前次失败经验后，模型的下一次尝试有什么变化。Reflexion 原论文把任务反馈转成反思文本，并在后续尝试中使用情节记忆，这个联系值得在 4.4.1 中明确说明。 [第四章 Reflection.py 上游代码](https://github.com/datawhalechina/hello-agents/blob/2eb1c7547018b519b85cb57acf5533f12d65bf8e/code/chapter4/Reflection.py) · [Reflexion 原论文](https://arxiv.org/abs/2303.11366)
- **用相同验收条件比较三种循环。** 当前三个例子分别展示了各自的工作方式，可以再选一个有固定答案和外部信息需求的小任务，记录正确率、模型与工具调用次数、总耗时和失败原因。Plan-and-Solve 原论文针对多步推理中的漏步和计算错误，ReAct 原论文强调行动获取的信息如何影响后续决策。比较时保留这些差异，学员更容易根据任务选择或组合循环。 [Plan-and-Solve 原论文](https://arxiv.org/abs/2305.04091) · [ReAct 原论文](https://arxiv.org/abs/2210.03629)
