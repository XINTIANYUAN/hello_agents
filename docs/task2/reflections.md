# Task2 学习心得

## 符号规则让行为可以追查

第二章把早期智能体讲得很具体。专家系统将领域知识写成规则，推理机根据事实触发规则，或从待验证的结论倒推需要收集哪些证据。SHRDLU 又把语言、规划和行动放进同一个积木世界。它们让我看到，规则设计的价值在于把「发生了什么」和「怎样得出结论」说清楚。任务环境一旦扩大，设计者就要继续处理例外、补充知识，并决定哪些状态会随动作改变。 [第二章 2.1 基于符号与逻辑的早期智能体](https://github.com/datawhalechina/hello-agents/blob/2eb1c7547018b519b85cb57acf5533f12d65bf8e/docs/chapter2/%E7%AC%AC%E4%BA%8C%E7%AB%A0%20%E6%99%BA%E8%83%BD%E4%BD%93%E5%8F%91%E5%B1%95%E5%8F%B2.md#21-基于符号与逻辑的早期智能体)

迷你 ELIZA 给出了一个可以逐行核对的例子。它先匹配正则，再把捕获的短语做代词转换，最后填入可选回复模板。读例子时，我会比较 `I need help with my project` 和 `Could you help with my project?`。两句话的请求相近，简化规则却会走到不同分支。同一个模板产生的语句即使听起来切题，也要回到匹配结果、事实和上下文检查它理解到了什么。这个习惯同样适合评估大模型生成的答复。 [第二章 2.2 构建基于规则的聊天机器人](https://github.com/datawhalechina/hello-agents/blob/2eb1c7547018b519b85cb57acf5533f12d65bf8e/docs/chapter2/%E7%AC%AC%E4%BA%8C%E7%AB%A0%20%E6%99%BA%E8%83%BD%E4%BD%93%E5%8F%91%E5%B1%95%E5%8F%B2.md#22-构建基于规则的聊天机器人) · [Weizenbaum 的 ELIZA 原文](https://courses.cs.umbc.edu/331/papers/eliza.html)

## 分工以后还要设计协作

明斯基的积木塔例子把找积木、抓取和放置分给专门的过程。我学到的是，拆分任务只是第一步。协作还依赖明确的结果交接，例如抓取模块必须告诉放置模块拿到的是哪块积木、抓取是否成功。失败也需要成为可传递的状态，才能由负责协调的一方决定重新定位、重试或停止。这样理解多智能体系统时，可以观察角色的决策权、它能看到的状态，以及收到失败反馈后由谁行动。 [第二章 2.3 马文·明斯基的心智社会](https://github.com/datawhalechina/hello-agents/blob/2eb1c7547018b519b85cb57acf5533f12d65bf8e/docs/chapter2/%E7%AC%AC%E4%BA%8C%E7%AB%A0%20%E6%99%BA%E8%83%BD%E4%BD%93%E5%8F%91%E5%B1%95%E5%8F%B2.md#23-马文明斯基的心智社会)

## 区分训练、任务状态和工具结果

预训练让模型通过数据获得可迁移的语言能力。强化学习可以用奖励改善序贯决策策略。实际执行一个任务时，工具反馈又可以更新当前可见的信息。例如，第一章旅行助手查到天气后，把结果放进下一轮提示，模型据此决定怎样搜景点。这里变化的是本次任务的上下文。把这三层分清楚，就容易判断一次改进该从训练数据、提示与历史，还是工具接口入手。 [第二章 2.4 学习范式的演进与现代智能体](https://github.com/datawhalechina/hello-agents/blob/2eb1c7547018b519b85cb57acf5533f12d65bf8e/docs/chapter2/%E7%AC%AC%E4%BA%8C%E7%AB%A0%20%E6%99%BA%E8%83%BD%E4%BD%93%E5%8F%91%E5%B1%95%E5%8F%B2.md#24-学习范式的演进与现代智能体) · [第一章旅行助手代码](../../code/chapter1/FirstAgentTest.py)

把这些思路放到灵巧手仿真，可以从一项抓取任务开始。语言模型把「把积木放进指定托盘」转成场景内的目标，轨迹与仿真模块返回候选轨迹和碰撞、关节限位检查，控制模块负责仿真动作。失败后让上层根据仿真记录选择换一条候选轨迹或结束任务。验收可以检查每次接受轨迹的决定是否都有对应的仿真结果，以及失败是否被如实记录。
