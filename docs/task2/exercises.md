# Task2 · 第二章习题解答

本章七道题涉及符号推理、分布式协作、强化学习、预训练和 LLM 智能体。第 3 题包含可以在终端复现的 ELIZA 练习。医疗和代码审查部分是系统设计题。[Datawhale 第二章习题][exercises]

## 1. 物理符号系统假说

**充分性。** 具备足够规模的物理符号系统经过适当组织，拥有实现通用智能行为所需的手段。这里的物理符号系统能构造、解释和变换符号结构。例如，规则中的表达式可以指向外部对象，也可以指向可执行操作。普通计算机或规则库能操作符号，并不能由此推得它已经具备通用智能。[Newell 与 Simon 原文][pssh]

**必要性。** 如果一个系统已经表现出通用智能，那么分析它的实现时应能发现物理符号系统。这个方向从通用智能推向符号系统。两项论断都是关于实现机制的经验假说。[Newell 与 Simon 原文][pssh]

**实践挑战。** 专家系统依靠人工提取和维护规则，难以覆盖隐性知识、不断变化的例外与模糊语境。规则增加后会产生冲突、推理分支和较大的维护负担。SHRDLU 在积木世界里能把话语与对象、行动对应起来，扩展到开放世界时，还要解决感知、符号与现实的对应及常识问题。这些限制挑战了以人工符号规则为主要手段的通用化设想，尚不足以在逻辑上排除任意规模、任意组织方式的符号系统。[第二章 §2.1][symbolic]

**怎么看 LLM 智能体。** 以整个系统为边界，消息、JSON 工具参数、显式规则和工具执行都有可观察的符号操作。以模型内部为边界，模型主要通过训练得到的向量、权重和连续激活计算，输入端 token 的离散性无法单独建立其推理机制属于经典符号系统。现代智能体兼用了学习表示和显式符号机制，在具体任务上的效果也不足以验证假说所要求的通用智能。[第二章 §2.4.4][llm-agents]

## 2. MYCIN 与高风险领域的专家系统

**为什么难以应用。** MYCIN 的实验价值和临床部署需要不同证据。可能的落地障碍包括以下几类。这里分析的是可能因素，无法从中为历史决策指定唯一原因。[MYCIN 项目原著][mycin]

- **日常工作流。** 医生另外录入病史和化验信息会增加时间和抄录错误。电子记录、检验、药房系统的集成也需要可靠的数据接口和统一单位。
- **临床验证。** 开发环境得到的成绩需要用不同机构、人群和时间段的数据验证，观察漏报、误报、实际工作耗时和医生使用后的效果。
- **伦理、责任与接受度。** 系统如何显示依据、错误发生后如何追踪决策、医生是否会被大量提示干扰，都影响使用。数据保护、责任分工和变更管理也需要在上线前落实。

**今天的设计。** 把目标限定为面向临床专业人员的诊断决策支持。读取有权限的病历和检验，保留来源、单位和时间。检索机构批准的指南与本地规程，用模型提取关键信息、整理证据和相反线索，用确定性规则检查输入完整性及适用条件。缺少关键数据、证据冲突或病例超出范围时，显示不确定性并交由医生处理。临床人员可以确认、驳回或修改建议。系统记录使用的资料和规则版本，保护患者信息。先离线做多机构和分人群评估，再用静默试点考察真实工作流和人机协作表现。[医疗 AI 良好机器学习实践指导原则][gmlp]

**规则更合适的领域。** 在工业设备联锁中，保护门开启时禁止启动，复位需满足明确定义的状态条件。输入、动作和例外均可审计，规则可以逐条测试。另一个例子是结构化工程文件的单位、尺寸和允许区间检查。接近人类表达的工单备注可以由模型提取，正式的通过、拒绝或复核仍可按规则和可追溯证据执行。[第二章 §2.1.2][expert-systems]

## 3. 扩展 ELIZA

### 增加话题规则与对话记忆

在[课程原版 ELIZA](../../code/chapter2/ELIZA.py)的基础上，[扩展版](../../code/chapter2/ELIZAExtended.py)增加了四条话题规则。

| 输入模式 | 响应行为 |
| --- | --- |
| `I work as ...` | 记录职业，追问用户喜欢这份工作的哪一部分。 |
| `I am studying ...` | 追问用户对学习内容中的哪一部分最感兴趣。 |
| `I enjoy ...` | 追问用户最喜欢这项爱好的哪一部分。 |
| `I feel stressed about ...` | 追问什么最让用户感到压力。 |

`My name is ...` 和 `I am N years old` 分别录入姓名和年龄。`What is my name?`、`What is my age?` 和 `What is my occupation?` 从字典回忆信息，字段空缺时说明用户尚未告知。新录入的值覆盖同一字段的旧值，状态保留到当前进程结束。扩展规则未命中时，程序沿用原版匹配、代词替换和默认应答。[第二章 §2.2][eliza]

```bash
.venv/bin/python code/chapter2/ELIZAExtended.py
```

在 Python 3.11.17 的实际运行中，原版与扩展版均以退出码 `0` 结束。扩展版命中四条新话题规则，回忆出 Lin、28 岁和 GIS analyst，录入新年龄后回忆为 29 岁。独立进程显示姓名尚未录入，`I need my notebook` 也继续触发原版的规则和代词替换。[终端验证记录](learning-notes.md)

### 为什么开放域规则容易组合爆炸

假设选择回应需要同时区分 5 类话题、4 类表达意图、3 种语气和 4 种对话状态。若每种组合单独配置，最多需要 $5 \times 4 \times 3 \times 4 = 240$ 个分支。一般地，$k$ 个条件轴分别有 $n_1, n_2, \ldots, n_k$ 种取值，逐组枚举的规模为 $\prod_{i=1}^{k} n_i$。如果每个轴都有 $m$ 种取值，就是 $m^k$。考虑最多 $t$ 轮上下文、每轮有 $m$ 种模式，可能的模式序列也可达到 $m^t$。

这是直接枚举的规模示例。抽取姓名、年龄、职业等槽位，分别判断话题和语气，并让模板复用状态，可以显著减少规则。开放域中的多义词、否定、纠错和跨轮指代仍会产生跨条件交互，需要同步维护匹配顺序、冲突处理和回归用例。[第二章 §2.2][eliza]

## 4. 心智社会、模块故障与现代多智能体

**`GRASP` 失效时。** 图 2.6 中，`GET-BLOCK` 依靠 `REACH` 和 `GRASP` 等过程完成取块。抓握失败后，上游仍可能找到积木并把手移到附近，但后续放置缺少已抓住积木这一前置条件。若没有失败反馈，`BUILDER` 可能反复触发 `ADD-BLOCK`。如果抓握过程能够报告失败，上层可以重试、改用其他抓握模块或停止当前任务，具体取决于是否实际配置了替代路径。[第二章图 2.6 与 §2.3][society]

**去中心化协作的收益和代价。** 局部单元只负责一个能力，便于复用、替换和并行处理，局部反馈能改变控制流。另一方面，子系统之间需要协调状态和时序。失败传播、互相等待和重复动作更难定位。若关键能力只有一个实现，去中心化也无法保证该任务能容错。[第二章 §2.3.3][society-implications]

| 系统 | 与心智社会的联系 | 典型差异 |
| --- | --- | --- |
| CAMEL Workforce | 分解任务并由不同工作节点处理，再汇集局部产出。 | Workforce 编排任务生命周期，任务代理负责拆分，协调代理负责分配。常用连接是任务接口与消息。[CAMEL 官方文档][camel] |
| MetaGPT | 产品、设计、开发等角色分工，阶段性产物供后续角色使用。 | 把人类软件团队的标准流程编码为角色协作与结构化交付，各角色可使用 LLM 做多步推理。[MetaGPT 论文][metagpt] |
| CrewAI | 专门化代理按任务协作，并向下一处理步骤提供结果。 | 可使用顺序执行，也可采用经理代理协调的层级流程。控制结构通过应用配置表达。[CrewAI 官方文档][crewai] |

**LLM 时代仍有参考价值。** 明斯基强调可把整体智能解释为组成过程之间的组织与交互。如今组成单元可以是简单验证器，也可以是拥有推理能力的 LLM 代理。应根据任务拆分是否清楚、上下文是否可共享、结果是否能独立验证来决定协作结构。多个强模型彼此传递未经验证的判断，仍可能放大同一个错误。[第二章 §2.3][society] · [MetaGPT 论文][metagpt]

## 5. 强化学习、监督学习和序贯决策

**AlphaGo 怎样试错。** 初版 AlphaGo 先用人类棋谱训练策略网络以预测落子，再让策略通过自我对弈探索。每盘的胜负为先前的一连串落子提供延迟反馈，用于改进策略。价值网络学习从局面估计胜负前景，对弈时结合策略、价值和树搜索决定落子。初版有棋谱初始化，AlphaGo Zero 从围棋规则和自我对弈开始。[Google DeepMind 的 AlphaGo 技术说明][alphago] · [AlphaGo Zero 原作者说明][alphago-zero]

**为什么适合序贯任务。** 当前动作会改变下一状态，短期选择也会影响未来能获得的奖励。强化学习以累计回报为目标，需要解决探索与利用、延迟回报归因以及策略变化后的数据分布问题。监督学习通常以给定输入及目标输出训练，例如观察画面后预测专家按键。强化学习训练使用交互产生或日志记录的观察、动作、奖励、下一状态与终止标志，无需专家逐步标注正确动作。离线强化学习可使用既有交互轨迹，仍需要足以支持策略改进的覆盖。[Sutton 与 Barto《强化学习》][rl]

**超级马里奥怎么训练。** 两种方案的数据不同。

| 方案 | 数据 | 优势与局限 |
| --- | --- | --- |
| 监督学习 · 行为克隆 | 人类试玩的连续画面或状态、按键及时间戳。演示最好覆盖正常通关、岔路和失误恢复。 | 快速模仿已有策略，训练成本取决于示范。模型进入演示较少访问的状态时，错误可能随时间累积。 |
| 强化学习 | 可交互、重置的模拟器，合法动作和每步反馈。记录状态或观测、动作、奖励、下一状态和是否结束。 | 可以用通关、进度和死亡等信号训练长期策略，需要较多交互，还要检查奖励是否诱导反复刷局部收益。 |

如果模拟器能快速重置并安全试错，我选强化学习作为主方法，用关卡完成率和未见关卡上的表现评估。有高质量演示时，可以先行为克隆取得稳定起点，再用强化学习改进。只能获得专家录像及动作标签时，监督学习更实际。[Sutton 与 Barto《强化学习》][rl]

**在 LLM 的训练里做什么。** 强化学习可用于后训练，根据人工偏好或可验证结果给回答、推理任务或工具交互轨迹反馈信号，优化模型的策略。在 InstructGPT 的公开流程中，先用人类示范监督微调，再用人类排序训练奖励模型，并以强化学习优化回答。对有可核验结果的任务，也可以使用测试或答案判定提供反馈。奖励和真实目标的差距仍要靠独立评估发现，预训练获得语言能力与后训练塑造行为在目标上各有侧重。[OpenAI 的 InstructGPT 技术说明][instructgpt]

## 6. 预训练、微调与知识获取

**为什么能缓解知识获取瓶颈。** 符号主义知识库依赖专家把知识写成规则、事实或关系。预训练用语料自身构造监督信号，如预测遮蔽词或下一个 token，从大规模数据学习共性表示。许多下游任务可以复用基础模型，并用较少的专门数据调优。显式规则可逐条查看和修改。神经参数则分布式、隐式地编码关联，难以定位为一条可维护的事实。瓶颈也转移到数据质量、训练成本、验证和知识更新。[第二章 §2.4.3][pretraining] · [BERT 原论文][bert]

| 互联网预训练可能引入的问题 | 缓解办法 |
| --- | --- |
| 偏见、语言和人群覆盖不均 | 检查数据来源与覆盖，改善代表性，单独报告不同语言和人群上的结果，复核高风险用途。 |
| 错误、矛盾、重复或陈旧内容 | 做数据质量检查和去重。对时效性强的事实使用来源明确的检索和时间标记，用独立数据评估准确性。 |
| 私密信息及许可不明内容 | 做来源清单和许可审查，筛除敏感标识，评测训练数据泄露，并建立访问控制和处理反馈的机制。 |
| 评测题混入训练集 | 按来源、相似内容和时间进行隔离，在训练前去污染，增加独立保留的新样本。 |

**会不会被取代。** 我的判断是通用模型打底、下游按任务适配会长期存在。部署端可能更多使用检索、工具和上下文学习，少做整模型微调。参数高效微调仍适合稳定的专业表达和反复遇到的任务。未来如果持续学习能在可控成本下稳定更新知识、降低遗忘并可核查变化，训练和适配之间的界线可能变得更模糊。这是对技术演进的判断。[第二章 §2.4.3][pretraining] · [BERT 原论文][bert]

## 7. 三个时代的智能代码审查助手

### 1980 年代的符号主义方案

输入用版本差异与可获得的源代码，不依赖现代 PR 平台。为目标语言准备解析器，从抽象语法树、控制流图和符号表提取函数签名、变量读写等事实。用手工规则检查已知模式，例如不可达分支、未初始化变量和违反编程规范的代码，记录触发文件与位置。用模板生成变更摘要和确定的修复建议。难点在于语言和项目定制成本，业务意图、跨文件约束及新缺陷很难完整写成规则。[第二章 §2.1][symbolic]

### 约 2015 年的深度学习方案

收集历史变更、审查意见、修复关联和可靠标签，把可获得的 diff、语法信息和测试结果编码为特征。用当时可用的 CNN 或循环网络训练缺陷风险分类和排序，将高风险变更交给人工。粗略摘要可以结合变更统计、固定模板和检索相似变更。常见挑战是审查意见会带噪声，未被指出的缺陷难作标签，不同仓库间的数据分布也会变化。因此应该按仓库和时间做保留集评估，避免近重复代码同时出现于训练和评估中。[第二章 §2.4.1][connectionism]

### 今天的 LLM 智能体方案

| 模块 | 对应代码审查职责 |
| --- | --- |
| 感知 | 读取 PR 描述、base/head 差异、仓库规则和 CI 状态，形成带版本和行号的变更观察。 |
| 规划和模型 | 先说明修改涉及的行为与调用方，再按风险挑出需要核实的问题，例如边界输入、缺失分支和与测试覆盖有关的疑点。 |
| 记忆 | 在本次审查中保留已看文件、调用关系、候选发现和证据。检索当前版本的仓库约定和相关实现，在基准提交变化后更新上下文。 |
| 工具与执行 | 读取相关符号和调用位置、查询测试结果、调用已有静态分析。需要执行已有测试时使用隔离环境和明确的时间预算。 |
| 观察与反馈 | 将工具结果带回模型，核对初步假设，去重并修正行号。输出实现摘要、可复核的发现、影响和建议，注明哪些结论仍有疑点。保留维护者的审批与合并决定。 |

例如，PR 修改列表分页逻辑时，助手先读参数校验和接口约定，然后查看变更函数与测试。假设接口要求始终校验页大小，但代码在列表为空时提前返回，可以检查空列表用例和提前返回的位置，再报告能从代码和测试结果证实的行为。这是设计例子。[第二章图 2.10 与 §2.4.4][llm-agents]

**三个阶段的区别。** 符号方法能可靠检查已定义的规范和特定模式。深度学习能从过往样本判断风险并排序。LLM 智能体进一步能阅读描述和代码、按需补取跨文件上下文，用静态分析和测试核实结论，并把结果表达成可操作的审查意见。随着这些能力组合，跨项目、可交互的审查助手逐渐可行，其审查质量仍取决于仓库上下文、验证覆盖和误报处理。
